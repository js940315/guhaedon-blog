작성일: 2026-08-04
작성 주체: Cowork 세션 (매일 자동발행 작업을 1년 가까이 실행해온 쪽)
인수 대상: Claude Code

## 0. 이 문서를 만든 이유 (가장 먼저 읽을 것)

**현재 구조는 "글은 쌓이는데 수익이 0에 수렴"하는 상태다.**

- 총 발행글 345개, 도메인 개설 2025-05-24 (약 14개월)
- 최근 12일 동안 120개를 쏟아냈다 (= 전체 콘텐츠의 35%)
- 그런데 **자연 검색 유입이 사실상 없다**

발행 파이프라인 자체는 정상 작동한다. 기술 SEO도 정상이다.
**따라서 이 프로젝트에서 지금 필요한 건 "더 많은 글"이 아니라 "왜 안 먹히는지에 대한 진단과 전략 수정"이다.**

Claude Code에게 기대하는 것:
1. 아래 진단이 맞는지 데이터로 검증
2. `COWORK_TASK_PROMPT.md`(현재 실행 스펙)를 **근본적으로 다시 설계**
3. 345개 기존 글 / 823개 태그 / 16개 카테고리에 대한 정리 작업 실행

**주의: 도구를 Cowork에서 Claude Code로 옮기는 것 자체는 유입 문제를 해결하지 않는다.**
환경 이전이 "진전을 본 느낌"만 주고 본질을 미루게 되는 걸 경계할 것.

## 1. 프로젝트 개요

- **사이트**: https://savemoney119.com (WordPress, Rank Math SEO, IndexNow 플러그인 활성)
- **주제**: 절약 / 정부지원금 / 생활비 (한국 애드센스 최대 경쟁 니치)
- **타겟 독자**: 스마트폰으로 읽는 40대 이상
- **수익 모델**: 구글 애드센스 (Auto Ads 앵커+전면)
- **현재 운영 방식**: Cowork 예약 작업이 매일 06:30에 실행 → 10개 글을 07:00부터
  60~90분 난수 간격으로 `status="future"` 예약 발행

## 2. 2026-08-04 점검에서 확인된 사실 (전부 실측, 추측 아님)

### 2-1. 기술 SEO — 정상. 여기서 고칠 건 거의 없다

방금 발행된 글을 Googlebot User-Agent로 직접 받아서 확인:

```
status 200, HTML 207KB
<title> 정상 출력
meta robots  -> follow, index, max-snippet:-1, max-image-preview:large
canonical    -> 정상 (자기 자신)
og:image     -> 정상
meta description -> 정상 (Rank Math v2 패치가 실제로 반영되고 있음)
H1 1개 / H2 5개 / JSON-LD 2개
```

- `robots.txt`: `Allow: /` + `Sitemap: https://savemoney119.com/sitemap_index.xml` + Daum 인증코드
- `sitemap_index.xml` 정상, 발행 시각에 맞춰 `lastmod` 갱신됨
- IndexNow 플러그인 활성 (Bing/Yandex 자동 색인 요청은 이미 돌고 있음)
- 응답속도 0.09초 — 서버 성능 문제 아님

**결론: "SEO 세팅이 잘못돼서 노출이 안 된다"는 가설은 기각.**

### 2-2. 검색 노출 실측 — 개별 글이 안 잡힌다

- 네이버 웹검색 `savemoney119` → **홈페이지 1건만 색인. 개별 글 0건.**
- 어제 발행한 글 제목을 거의 그대로 네이버 검색
  (`저소득층 문화누리카드 연 14만원 잔액 소멸`)
  → 상위 10개가 **네이버 블로그 3 + 티스토리 3 + 개인 워드프레스 3.
  우리 글은 아예 없음.**
- 구글 `site:` 유사 조회 → 홈페이지와 `open.savemoney119.com/hub/`만 확인됨

### 2-3. 발행 이력이 극도로 불규칙 (구글이 싫어하는 패턴)

```
2025-05: 23    2025-06: 38    2025-07:  6
2025-08 ~ 2025-11: 0 (5개월 완전 공백)
2025-12:  8    2026-01: 73    2026-02: 36
2026-03: 11    2026-04:  4    2026-05:  6
2026-06: 0
2026-07: 101   2026-08: 39 (4일 만에)
```

최근 14일 일별: 7/23부터 하루 10~20개로 급증.
**전체 글의 35%가 최근 12일치.**

`COWORK_TASK_PROMPT.md`는 발행 "간격"을 60~90분 난수로 흩어서 스팸 필터를
피하려 하지만, **scaled content abuse 판정은 간격이 아니라 이 총량 곡선에서 나온다.**
간격 랜덤화로는 이 신호가 사라지지 않는다.

### 2-4. 분류 체계 붕괴 — thin archive 대량 생성 중

- **태그 823개 / 글 345개.** 조회한 100개 중 **100개가 글 1개짜리 태그.**
  → 콘텐츠가 1건뿐인 아카이브 페이지를 수백 개 만들고 있음
- 태그 표기 불일치: `절약습관`(12) vs `절약 습관`(4) 별도 존재
- 카테고리 16개, 그중 이모지/띄어쓰기 차이로 갈라진 **중복 3쌍**:
  - `금융·대출 💳`(62) / `금융·대출💳`(3)
  - `정부 지원 🏦`(61) / `정부 지원🏦`(3)
  - `물가 절약`(2) / `물가절약`(1)
- 그 외 의미 중복: `정부지원금`(74) / `정부 지원 🏦`(61),
  `생활비 절약`(3) / `물가 절약`(2), `절약 이야기`(11) / `경제 인물`(1)
- 빈 카테고리: `⚡실시간 지원금`(0), `Uncategorized`(7)

**원인**: `wp_publisher.py`의 `get_category_id()`가 완전일치 실패 시
부분일치로 넘어가고, 그것도 실패하면 `auto_create=True`로 새로 만든다.
스크립트마다 카테고리명을 조금씩 다르게 넘겨서 중복이 누적됐다.

### 2-5. WP-Cron 불안정 (기존에 파악된 이슈, 안전장치 있음)

- 2026-08-03 발행분 중 2건(07:00, 08:14 슬롯)이 예약 시각이 8시간 넘게 지나도록
  `status=future`에 멈춰 있었음 → 오늘 실행에서 강제 `publish` 처리함
- 저트래픽 사이트라 WP 기본 pseudo-cron이 방문자 트래픽에 의존해서 발생
- `COWORK_TASK_PROMPT.md` 7-1항에 재확인·강제발행 절차가 이미 명시돼 있음

### 2-6. `fetch_sources.py`가 오늘 동작하지 않았다

Cowork 리눅스 샌드박스에서 구글뉴스 RSS 호출이 응답하지 않아
`candidates.json`이 갱신되지 않았다(파일 타임스탬프가 8/3에 멈춤).
**오늘은 NaverSearch MCP(`search_news`, `search_kin`)로 대체해서 소재를 잡았고,
결과적으로 그쪽이 훨씬 나았다** — 실시간성·한국어 연관검색어 품질 모두 우위.

→ `fetch_sources.py`의 구글뉴스 RSS 의존을 재검토할 것.

## 3. 아직 확인 못 한 것 (사용자에게 받아야 함 — 로그인 필요)

이 세 가지가 없으면 진단이 추측에 머문다. **작업 시작 전에 사용자에게 요청할 것.**

1. **구글 서치콘솔 "페이지" 리포트 숫자**
   - 색인됨 / 색인 생성 안 됨 각각 몇 건인지
   - 특히 **"크롤링됨 – 현재 색인이 생성되지 않음"** 건수
   - → 이 숫자 하나로 *색인 문제인지 순위 문제인지*가 확정된다.
     둘은 처방이 완전히 다르다.
2. **`open.savemoney119.com/hub/`의 정체**
   - 구글 검색에서 본체(`savemoney119.com`)보다 먼저 노출됨
   - 별도 운영 중인지, 콘텐츠가 겹치는지 확인 필요 (겹치면 카니발라이제이션)
3. **수익 목표와 기간**
   - 애드센스 승인 상태 / 현재 월 수익 / 목표 금액과 시점
   - → "하루 10개를 유지할지 줄일지"가 여기서 갈린다

부가 확인 사항: 네이버 서치어드바이저 / 구글 서치콘솔 / 빙 웹마스터에
사이트·사이트맵이 실제로 등록돼 있는지 (미등록이면 색인 속도만 느려짐)

## 4. 진단 (확정 / 가설 구분)

### 확정된 것
- 기술 SEO는 문제가 아니다 (2-1)
- 분류 체계가 망가져 있고 thin archive를 대량 생성 중이다 (2-4)
- 발행량 곡선이 비정상적으로 급증했다 (2-3)

### 가장 유력한 가설 (검증 필요)

**"information gain(원본 정보 가치)이 없어서 순위가 안 나온다."**

현재 글은 복지로·정부 보도자료에 이미 있는 내용을 잘 정리한 것이다.
품질이 낮진 않다. 하지만 **"이 페이지가 아니면 얻을 수 없는 정보"가 0이다.**

같은 키워드에 3년째 글을 쌓아온 티스토리/네이버 블로그를 이길 근거가
구조적으로 없다. 구글의 helpful content 판단에서 이게 결정적이다.

부수 가설:
- **네이버는 구조적으로 어렵다.** 네이버 통합검색은 블로그/카페에 자리를
  몰아준다. 워드프레스 개별 글이 웹검색 탭 밖으로 나가기 어렵다.
  → 네이버 유입을 노린다면 채널 전략 자체를 재검토해야 한다.
- **하루 10개 증량이 오히려 역효과일 가능성.** 위 2-3의 곡선 + 정형화된
  템플릿(모든 글이 동일한 H2 5개 구조, 동일한 CTA 위치, 동일한 FAQ 5개)이
  패턴으로 읽힐 수 있다.

## 5. Claude Code가 해야 할 일 (우선순위 순)

### P0 — 진단 확정 (다른 작업보다 먼저)
- [ ] 사용자에게 3장의 정보 요청 (위 3번 항목)
- [ ] 서치콘솔 수치 확보 후, **색인 문제 / 순위 문제 중 무엇인지 확정**
- [ ] 확정 전까지 아래 P1~P3의 대규모 실행은 보류할 것

### P1 — 분류 체계 정리 (진단과 무관하게 해야 하는 작업)
- [ ] 중복 카테고리 3쌍 병합 (이모지/띄어쓰기 변종 → 하나로 통일)
- [ ] 의미 중복 카테고리 통합, 최종 5~7개 수준으로 축소
- [ ] 빈 카테고리(`⚡실시간 지원금`) 삭제, `Uncategorized` 7건 재분류
- [ ] 823개 태그 → 글 2건 이상인 태그만 남기고 정리 (목표 50개 이하)
- [ ] 태그 표기 통일 (`절약습관` / `절약 습관` 등)
- [ ] 정리 후 `wp_publisher.py`의 `get_category_id()` **`auto_create=False`로 바꾸고
      허용 카테고리 화이트리스트를 강제**할 것 (재발 방지)
- [ ] 태그 아카이브에 `noindex` 적용 검토 (Rank Math 설정)

### P2 — 실행 스펙 재설계 (`COWORK_TASK_PROMPT.md`)
현재 스펙은 "하루 10개를 안전하게 뿌리는 법"에 최적화돼 있다.
**"검색에서 이기는 법"으로 목적 함수를 바꿔야 한다.**

- [ ] **발행량 재설정**: 10개/일 유지가 타당한지 데이터로 판단.
      줄인다면 몇 개로, 남는 리소스를 어디에 쓸지 함께 설계
- [ ] **information gain 확보 장치 설계**: 매 글에 "여기서만 얻을 수 있는 것"을
      최소 1개 강제 (예: 직접 만든 계산표, 가구원수별 실수령액 시뮬레이션,
      지자체별 조건 비교표, 실제 신청 화면 캡처 등)
- [ ] **템플릿 획일성 완화**: 현재 모든 글이 H2 5개 + CTA 1개 + FAQ 5개로 동일.
      소재 유형별로 구조를 분기시킬 것
- [ ] **기존 345개 글 처리 방침 결정**: 리라이팅 / 통합 / 삭제(noindex) 기준 수립.
      얇고 중복된 옛 글이 사이트 전체 평가를 끌어내리고 있을 가능성
- [ ] **소재 수집 재설계**: 구글뉴스 RSS(`fetch_sources.py`) → NaverSearch MCP 전환 검토

### P3 — 코드 정리
- [ ] `_autopublish_YYYYMMDD*.py` 누적 파일 정리 (현재 10개 이상, 각 50~108KB)
- [ ] 매일 새 스크립트를 생성하는 방식 → 재사용 가능한 모듈 + 데이터 파일 분리
- [ ] git 저장소로 전환 (`.env.json`은 `.gitignore`)
- [ ] `fetch_sources.py` 타임아웃/실패 시 조용히 넘어가지 않고 알리도록 수정
