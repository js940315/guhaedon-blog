## 0. 이 시스템이 하는 일 (한 줄)

워드프레스 허브(savemoney119.com)가 매일 자동 발행되면, 그 허브로 사람을 보내는

## 2. ⭐ 제목 뽑는 순서 (여기가 승부처)

### 2-1. 공식

```
[한정어] + [핵심키워드] + [행동어]
```

- **핵심키워드** — 그날 허브의 focus keyword를 **글자 그대로** 쓴다. 바꾸지 않는다.
- **한정어** — 경쟁을 낮추는 장치. 아래 4종 중 하나를 반드시 붙인다.
  1. 지역 : `영동군` `통영시` `전북` (시·군 단위가 가장 강함)
  2. 대상 : `차상위계층` `1인가구` `탈퇴 회원` `가족 명의`
  3. 시점 : `8월` `추석 전` `마감 임박` `2차`
  4. 상황 : `전입` `앱 안 될 때` `문자 왔을 때` `안 보여요`
- **행동어** — `신청` `조회` `대상` `금액` `기준일` `언제` `방법`

### 2-2. 배분 — 소재 유형부터 판정한다

> **판정법**: 소재 앞에 시·군·구를 붙여서 말이 되면 A, 안 되면 B.
> ("영동군 민생지원금" → A / "따릉이 개인정보 유출" → B)

| | A형 (지역 분화 가능) | B형 (전국 이슈·사건) |
|---|---|---|
| 지역형 | 5 | — |
| 대상형 | 3 | 4 |
| 상황·문제형 | 2 | 4 |
| 절차·금액형 | — | 2 |

### 2-3. 제목 창고는 지식iN이다

지어내지 않는다. 네이버 지식iN에 실제로 올라온 질문을 **그대로 제목화**한다.
2026-08-09 세트의 3·4번이 그 방식으로 나왔다
("따릉이 이용해본 적도 없고 서울에도 안 사는데 해당자라고 문자가 왔어요").

보조 창고: 네이버 연관검색어, 자동완성, 카페 질문글.

### 2-4. 제목 금지사항

- 근거 없는 금액·날짜 단정 ("○○원 나온다")
- 확정 안 된 것을 확정으로 ("지급 확정")
- 같은 문장 구조 10개 반복 — 어미와 길이를 섞는다

### 2-5. 실측 참고 — 상위 노출 경쟁글 제목 패턴

> **출처 주의.** 원래 벤치마킹 대상이던 `m.blog.naver.com/andudtk12/*` 5건은
> **도메인 정책 차단으로 열지 못했다** (브라우저·WebFetch·인앱 3경로 전부 차단).
> 아래는 대체 근거다 — 네이버 검색API로 같은 소재(따릉이 유출·보상)의
> 유사도순·최신순 **120건 제목**을 수집해 뽑았다. 2026-08-10 수집.
> 본문을 못 읽었으므로 **이미지 배치 · 외부링크 위치와 문구 · 글 길이 ·
> 해시태그 총 개수는 여전히 미확인**이다. 그 4가지는 여기 적지 않았다.

1. **`｜` 로 검색어 2세트를 한 제목에 적재** — 2-1 공식에 없던 패턴이다.
   `[한정어+키워드+행동어]` 를 쓰고 `｜` 뒤에 **다른 행동어 세트**를 붙인다.
   - `따릉이 개인정보 유출 조회 방법｜30일 정기권 보상 대상·신청 여부`
   - `따릉이 개인정보 유출 보상｜30일권 지급일·유출 항목 총정리`

   롱테일 2개를 한 글로 먹는다. 제목이 길어지므로 **10건 중 2~3건만** 쓴다.
2. **자기대입 의문형 후크** — `나도 대상자일까?` `설마 내 정보도?` `내 정보도 포함됐을까?`
   2-3(지식iN 질문 원문을 제목화)과 잘 붙는다.
3. **숫자를 제목 앞쪽에** — `462만 명` `5,000원` `30일` `3개월`.
   단 2-4 금지사항대로 `_set_*.py` 에 없는 숫자는 쓰지 않는다.
4. **논란 프레임** — `고작` `딸랑` `허탈한` `털렸다`.
   **B형(전국 이슈)에서만** 쓴다. A형(지역 분화)에는 안 맞는다.

## 3. 본문 뽑는 법 — 슬롯 8칸을 채우면 끝

**재료는 새로 조사하지 않는다.** 그날 허브 세트 파일(`wp_lite/_set_YYYYMMDD.py`)에
이미 검증된 사실이 다 들어 있다. 거기서 옮긴다.

| 슬롯 | 내용 | 어디서 가져오나 |
|---|---|---|
| `intro` | 2문장, 결론 먼저 | 허브 `lead` |
| `table` | 3행 (대상/금액/기한) | 허브 `sum_rows` |
| `sub1` | 📌 궁금증형 소제목 | 새로 (질문형 X, "왜 안 보일까" O) |
| `body1` | 3~4문장, 답 | 허브 `faq` 답변 |
| `cta_mid` | 답 주기 직전 허브 링크 | 고정 |
| `warns` | 2~3줄 (기준일·기한·스미싱) | 허브 `WARN` |
| `cta_end` | 스포크 링크 (check 또는 apply) | 고정 |
| `question` | 여운형 질문 | 새로 |

해시태그 8개는 허브 `tags`를 확장한다. `#경제` `#일상` 같은 광범위 태그는 금지.

### 3-1. 링크 삽입 규칙 (어기면 유입이 안 생긴다)

글 1개당 링크는 **정확히 2회**.

1. **본문 40~50% 지점** — 답을 다 주기 직전. 항상 **메인허브**로.
2. **글 마지막** — 요약 후. **스포크(check/apply)** 로.

하지 말 것
- 글 맨 위 링크 → 네이버가 "외부 유출 목적 글"로 판단할 여지가 커진다
- 같은 URL 3회 이상 → 저품질 신호
- 단축 URL·리다이렉트 → 네이버가 특히 싫어한다. 원본 주소 그대로
- 워드프레스 본문 복붙 → **중복 콘텐츠로 양쪽 다 죽는다.**
  블로그는 "그 질문 하나"만, 워드프레스는 "전체 비교·기능"만 맡는다

### 3-2. 실측 참고 — 경쟁글 본문 구성

> 출처와 한계는 **2-5와 동일**하다. 본문 전체를 못 읽었으므로
> **제목과 검색 요약문에서 확인된 것만** 적는다. 링크 위치·이미지 배치는 미확인.

- **`구분 / 주요 내용` 2열 표가 사실상 표준.** 현행 `table` 슬롯(3행)은 방향이 맞다.
- **Q&A를 본문에 그대로 노출**하는 글이 많다 (`Q. 보상은 어떻게 받나요?`).
  현행 `sub1`+`body1` 은 서술형인데, 소재에 따라 Q&A 형태가 더 나을 수 있다.
  단 📌 소제목 규칙(3절 표)과 충돌하지 않게 **글당 한 곳만** 시험한다.
- **`✅ 한 줄 정리` 로 닫는 마무리**가 반복 관측된다.
  현행 `question`(여운형 질문)과는 다른 방식이다. 4절의 '댓글' 금지와는 충돌하지 않으므로
  `question` **앞에** 한 줄 요약을 넣는 실험은 가능하다.

> ⚠️ 위 3가지는 **아직 A/B 검증 안 된 가설**이다. 10건 전부에 적용하지 말고
> 2~3건에만 넣어 유입 차이를 본 뒤 확정한다.

## 4. 네이버 절대 규칙 (빌더가 강제 보정)

- ⛔ **마크다운 금지** — `**` `##` `` ` `` 를 쓰면 화면에 기호가 그대로 노출된다.
  "AI 글" 인식 → 즉시 이탈. 볼드 마킹도 네이버에 적용 안 된다.
- ⛔ **문장 중간 줄바꿈 금지** — 네이버가 화면 폭에 맞춰 감싼다. 하드 줄바꿈은 어색하게 끊긴다.
- 문단 구분은 **점자 빈칸 `⠀⠀⠀`(U+2800 x3)**. 일반 공백·빈 문자열은 복붙 때 사라진다.
- ⛔ **'댓글' 단어 자체 금지.** 구걸로 보여 역효과. 대신 맨 끝 여운형 질문.
- 이모지 장치는 글당 3~5개 이내 (`📌` 소제목 / `💡` 핵심 / `👉` 링크).
- 한 문장 60자 이내, 한 문단 2~3문장.

## 5. 매일 돌리는 순서

1. 워드프레스 허브가 06:47에 자동 발행된다 (`wp_lite/set_publisher.py`).
2. **초안 자동 추출** — 손으로 슬롯을 채우지 않는다.
   ```
   python _engine/make_spokes.py ../_set_20260809.py 0809 B
   ```
   그날 허브의 FAQ 14개(hub 4 · t1 5 · t2 5)를 스포크 10건의 뼈대로 옮긴다.
   FAQ는 이미 "사람들이 실제로 검색하는 질문" 형태이고 답변도 사실 검증을 거쳤다.
   **마지막 인자는 소재 유형(A/B)** — 소재 앞에 시·군·구를 붙여 말이 되면 A, 안 되면 B.
3. `spokes_MMDD_draft.json` 을 열어 각 post 의 `_todo` 를 처리한다.
   - 제목 → 지식iN·연관검색어를 보고 확정 (`_title_candidates` 는 후보일 뿐)
   - 표 '핵심·확인' 2줄 → 숫자·기한 위주로 짧게 고쳐 쓴다
   - 여운형 질문 → 소재에 맞게
   - `⚠ 원본 FAQ 답변이 짧아…` 표시가 붙은 글은 본문을 2~3문장 보강한다
   다 고쳤으면 `_todo` 를 지우고 `spokes_MMDD.json` 으로 rename.
   > `hub` 3개 URL은 **반드시 브라우저로 열어 200인지 확인**하고 넘어간다.
4. 저장소 루트에서 빌드:
   ```
   python _engine/build_spokes.py _engine/spokes_MMDD.json
   ```
5. `build_report.json` 의 `problems` 와 `cross_problems` 가 **둘 다 빈 배열**인지 본다.
6. `output/{MMDD}/네이버_스탠바이.html` 을 열어 복사 버튼으로 네이버에 붙여넣는다.
7. 10개를 한 번에 올리지 않는다. **60~90분 난수 간격**으로 하루에 걸쳐 분산한다.
   정확히 같은 간격으로 고정하면 정형화된 패턴이라 오히려 필터에 잘 걸린다.

## 6. 세트 유지 원칙

- 같은 소재를 **최소 3~5일 유지**한다. 매일 소재를 바꾸면 아무것도 안 쌓인다.
- 유지하는 동안 **각도만 바꾼다**. 8월 9일은 "쿠폰이 8월 중 앱 지급 + 3개월 소멸"이라는
  새 사실이 나와서 키워드 절반을 그쪽으로 옮겼다.
- 이미 쓴 키워드는 `state/seen_keywords.json` 에 누적한다. 겹치면 스킵하거나
  완전히 다른 각도로만 재구성한다.

## 8. 함정 모음

**깃허브 관련 (economy-blog 실측)**
- ⚠️ **Claude GitHub App을 이 repo에 개별 설치해야 한다.** 인증만으론 push가
  `remote: Resource not accessible by integration` 403으로 막힌다.
  https://github.com/apps/claude/installations/new 에서 이 repo를 명시적으로 선택.
- 커밋 메시지에 단독 `/` 를 넣지 말 것. Git Bash(MSYS)가 윈도우 경로로 변환해
  `'C:/Program Files/Git/' is outside repository` 로 커밋이 실패한다.
  여러 줄 메시지는 `git commit -F -` + heredoc.
- 세션 시작 시 `git branch -vv` 로 **detached HEAD 여부부터 확인**한다.
  economy-blog에서 45커밋이 detached HEAD에만 쌓여 push된 적 없던 사고가 있었다.

**콘텐츠 관련**
- 지역명만 바꾼 복제글은 네이버가 잡아낸다. **표의 숫자와 주의사항 한 줄은 실제로 달라야 한다.**
  빌더의 `cross_check()` 가 3회 이상 반복된 문장을 잡아준다.
- 내용 없는 랜딩을 여러 도메인에 걸쳐 연결하지 않는다 (구글 doorway page 판정 → 색인 삭제).
  허브에 실제로 쓸모 있는 기능(조회 위젯)이 있어야 그 선을 넘지 않는다.
- 트래픽 슬롯 구매·만료 도메인 매입 금지.

**파일 관련**
- 상태 JSON은 원자적으로 쓴다(tmp → `os.replace`). OneDrive가 파일을 NUL로
  손상시킨 사례가 있다.
- 이 저장소는 OneDrive 폴더 밖(`문서\GitHub\`)에 두는 편이 안전하다.
