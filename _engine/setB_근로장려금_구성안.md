## 1. 경쟁 상황 — 이미 붙었다 (2026-08-10 실측)

`근로장려금 반기 신청 9월` 검색 결과 20건 중 **대부분이 8/9~8/10 발행**이다.
8월 27일 정기분 지급일 발표가 불을 붙였다.

**그런데 두 갈래로 갈려 있다.**

```
"8월 27일 지급일"  이미 포화. 여기 들어가면 늦다
"9월 1일 반기신청"  아직 여유. 신청 시작까지 3주 남았고 검색 피크는 9월 초
```

**→ 반기신청 쪽으로 간다.** 지금 올려서 색인 시간을 벌고 9월에 익힌다.
이게 B세트(롱테일)의 정석이다. A세트라면 이미 늦어서 손대지 않았을 소재다.

**남들이 안 짚는 것** — 경쟁 글은 대부분 "기간·대상·지급일" 나열에 그친다.
아래 세 갈래가 실제로 사람마다 갈리는데 아무도 정면으로 안 다룬다.

## 2. ⭐ 아껴야 할 갈래 3개 (3-1-a절)

블로그는 규칙을, 허브는 판정을 맡는다. 이 셋이 허브를 눌러야 하는 이유다.

| # | 갈래 | 왜 갈리나 |
|---|---|---|
| ① | **내가 반기신청 대상인가** | **근로소득만** 있어야 한다. 사업소득이 조금이라도 섞이면 불가하고 5월 정기신청으로 가야 한다. 프리랜서·투잡은 본인도 헷갈린다 |
| ② | **5월에 이미 신청했는데 9월에 또 하나** | 이미 반기신청을 한 사람은 다시 안 해도 된다. 정기신청을 한 사람과 헷갈린다 |
| ③ | **왜 계산한 것보다 적게 들어오나** | 12월에는 **35%만** 들어온다. 나머지는 2027년 6월 정산. 이걸 모르면 "잘못 받았다"고 오해한다 |

③은 지급 시점(12월)에 검색이 폭발하는 갈래다. **지금 써두면 12월에 또 먹는다.**
B세트가 자산이 되는 지점이 정확히 여기다.

## 3. 워드프레스 허브 3페이지 구성

```
메인허브  근로장려금 반기신청 9월, 나는 대상인가
  ├ CTA① → 1차 (대상 확인)
  └ CTA② → 2차 (신청 절차)

1차  근로소득만 있는지 확인하기       ← 갈래 ①②
  ├ CTA① → 2차
  └ CTA② → 국세청 홈택스 (공식 종착)

2차  신청 방법과 12월에 받는 금액     ← 갈래 ③
  ├ CTA① → 국세청 장려금 상담센터
  └ CTA② → 홈택스 신청 화면
```

- **슬러그를 절대 바꾸지 않는다.** `/geunro-jangryeogeum-bangi/` 로 고정하고
  2027년 3월 하반기분, 2027년 9월 상반기분 때 **같은 슬러그를 덮어쓴다.**
  매년 새 글을 만들면 자산이 안 쌓이고 서로 카니발라이즈한다.
- `official` 은 반드시 **국세청·홈택스**로 종착한다. 상업 도메인 체인 금지.
- 각 페이지 `doubt` (다음 단계를 만드는 한 줄):
  - 허브 → "대상인 건 알겠는데, 근로소득만 있는 게 맞나?"
  - 1차 → "대상은 맞는데, 12월에 얼마가 들어오나?"
  - 2차 → "받고 나면 내년 6월에 뭘 더 해야 하나?"
